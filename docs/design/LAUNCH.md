# Launch plan

**Status:** living plan, updated 2026-10-08. Phase 1 code, Phase 2, Phase 3 code and the Phase 4 scrub
are merged; the owner's console tasks (Phase 1.1–1.3, 1.6) and the client-side Phase 3 items are open.
**Goal:** an open-source repo and a free hosted service that strangers can sign up for.

## 1. The pitch

> **A free todo list with no AI inside — your coding agent is the AI.**

The app holds tasks, projects and routines and makes no model calls. Whatever agent the user already
works in reaches it through a remote MCP server behind real OAuth 2.1: Claude Code, claude.ai, and
in principle any MCP client. The agent edits, reschedules, cleans up and reviews from inside the
user's normal workflow. Hosting is cheap because there is no inference bill, which is why the
service can stay free.

Two audiences, two framings:

| | Audience | Framing | Lands on |
|---|---|---|---|
| Hosted app | People who work in Claude Code, Cursor and similar tools | "A free todo list with no AI inside — your coding agent is the AI." | Landing page, Claude directory, r/ClaudeAI |
| Open-source repo | Developers who want to connect their own app to agents | "How I gave my todo app a remote MCP server with real OAuth 2.1, and what broke." | Show HN, the write-up, portfolio |

### Why this pitch and not a feature pitch

On features, Todoist's official MCP server ([Doist/todoist-mcp], MIT) covers everything we offer
and more. Our 13 tools fall within its 47:

- **Deadlines:** `add-tasks` and `update-tasks` take `deadlineDate`.
- **Bulk reschedule:** `reschedule-tasks` keeps recurring schedules intact.
- **Deletion:** `delete-object`.
- **Recurring-task history:** `find-activity`.
- **Streaks:** `get-productivity-stats`.

Every Todoist tool carries `readOnlyHint` and `destructiveHint` annotations. TickTick, Sunsama,
Akiflow, Amie and Superlist also run official remote MCP servers. A pitch built on capabilities
loses on the first comment.

Three things Todoist cannot match:

1. **Free without caps.** Todoist's MCP works on its free Beginner plan, but that plan caps users at
   5 projects and 1 week of reporting history. The cap would also limit "how's my routine going
   over four weeks?", unless the API is exempt (unverified; see §6). Our free service has neither
   cap.
2. **Open and self-hostable.** Todoist's MCP adapter is open source, but the tasks stay in
   Todoist's service. Here the whole stack runs on anyone's own Neon project.
3. **The story.** One engineer built a todo app for their own workflow, then built its OAuth server
   so agents could use it, and documented what broke.

### Evidence that the workflow is real

Read-only production counts, 2026-10-03:

| Measure | Value |
|---|---|
| Tasks | 548 (208 in the last 30 days) |
| Tasks generated by routines | 247 (45%) |
| Tasks with a hard deadline | 65 (12%) |
| Accounts | 2; one has ≥10 tasks |
| MCP connections | 1 |

The owner uses the app daily, and routines carry almost half the load. Those routines are what give
the agent something worth reasoning about in the demo. The service has never had a second real
user, which is why Phase 1 exists.

### What the pitch rules out

- **Adding tools to close the gap with Todoist.** 13 tools that do the job are enough.
- **Any in-app AI.** It would contradict the headline and add a bill.
- **A paid tier.** That also keeps us inside Vercel Hobby's non-commercial terms.
- **Native or desktop wrappers.** A PWA covers "feels like an app."
- **Claiming "any coding tool" before testing it.** Phase 3 is where that claim gets earned.

## 3. Phases

Each phase ends in something checkable. Phases 1–3 can overlap. Phase 5 needs Phase 2's landing
page and Phase 3's compatibility table. Phase 6 needs everything.

### Phase 1: Safe for strangers

1. **Own Google OAuth client.**
   - Create a Google Cloud Web client with redirect URI `{NEON_AUTH_BASE_URL}/callback/google` for
     the production branch.
   - Register it under Neon Console → Settings → Auth → Add OAuth provider.
   - Set the consent screen to *In production*. With only openid, email and profile scopes, Google
     requires no verification and imposes no 100-user cap.
2. **Own email sender.**
   - Configure custom SMTP in Neon Auth, sending from an address on `g7xu.dev` (D6).
   - Set SPF, DKIM and DMARC on the domain.
3. **Neon Auth production checklist.**
   - Set the app name.
   - Turn off "Allow Localhost" on the production branch.
   - Confirm `todo.g7xu.dev` is a Trusted Domain.
4. **Privacy policy, terms and support pages** at `/privacy`, `/terms` and `/support`. The policy
   covers:
   - data collected: email, Google profile, tasks, routines, OAuth grants and tokens, logs;
   - processors: Vercel, Neon on AWS, Google, the email provider;
   - retention, a contact address, and how to delete or export data.
5. **Delete account and export data** in Settings.
   - Export downloads tasks, projects and routines as JSON.
   - Delete removes app data and the Neon Auth user, and revokes every grant.
6. **Abuse floor.**
   - One Vercel WAF rate-limit rule on `/api/auth/*`. The browser reaches Neon through our own
     handler, so Vercel sees this traffic.
   - Usage alerts on Neon and Vercel.

*Done when:* a fresh Google account and a fresh email address can each sign up, and the consent
screen and email both show our name and domain. Deleting the account removes it; a later sign-in
starts empty.

### Phase 2: Looks like an application

1. **Name and icon (D3).**
   - Make one SVG master.
   - Export the favicon, `app/icon.png`, `app/apple-icon.png`, 192 and 512 PNGs, and a maskable 512.
   - The same mark serves the directory listing and Product Hunt.
2. **`app/manifest.ts`**
   - Set `display: "standalone"` and `start_url: "/upcoming"`.
   - Follow `node_modules/next/dist/docs/01-app/02-guides/progressive-web-apps.md`.
   - Push notifications are out of scope.
3. **`app/opengraph-image`**, so shared links render a card.
4. **Delete the starter SVGs** in `public/`.
5. **Mobile pass.**
   - First, check the authed views at 375 px via `/auth-harness`.
   - Collapse the sidebar into a sheet below `md`, and keep the Upcoming board scrolling sideways.
   - Fix only what breaks.
6. **Signed-out landing page at `/`.** Signed-in users still redirect to `/upcoming`. The page
   carries:
   - the headline;
   - a muted autoplay clip (from Phase 5);
   - per-client setup snippets (from Phase 3);
   - three example prompts;
   - Sign in;
   - links to the repo, the write-up, privacy, terms and support.

*Done when:* the app installs to a phone home screen and opens standalone with our icon, a pasted
link shows the OG card, and a signed-out visitor sees the landing page.

### Phase 3: Works in your agent

1. **Compatibility matrix.**
   - Connect each client end to end and run the same three prompts: Claude Code, claude.ai, Cursor,
     VS Code (Copilot agent mode), Codex CLI and Gemini CLI.
   - Record per client: auth method used (CIMD, DCR or token), redirect URI shape, pass or fail, and
     the setup snippet that worked.
   - Fix what fails. If a client needs a custom-scheme redirect, widen `isRegistrableRedirectUri`
     to RFC 8252 private-use schemes with a test per client.
   - Publish the table as `docs/CLIENTS.md`.
2. **Personal API token (D9).** A Settings page that issues a revocable bearer token scoped to
   `tasks:read`/`tasks:write`, for clients whose OAuth flow cannot be fixed. It reuses the existing
   hashed-token store and grant revocation.
3. **Tool annotations.**
   - `readOnlyHint: true` on `list_tasks`, `list_projects`, `list_routines` and
     `get_routine_history`.
   - `destructiveHint: true` on `delete_task` and `bulk_delete`.
   - `destructiveHint: false` on the other writes.
4. **Reword `INSTRUCTIONS`** to describe the data model without directing the agent's behavior.
5. **OAuth conformance for the Claude directory.**
   - The protected-resource `resource` must equal the listed MCP URL exactly, so production
     `APP_URL` must be `https://todo.g7xu.dev`. Verify it.
   - `https://claude.ai/api/mcp/auth_callback` is accepted.
   - Metadata advertises CIMD.
   - The token endpoint takes form-urlencoded bodies.
   - Re-run `npm run test:e2e:smoke` against production.
6. **Demo account.**
   - Extend `scripts/seed-routine-demo.ts` into an account with about six weeks of synthetic routine
     history, some deadlines and a few overdue items.
   - Add a one-command reset.
   - It serves as the directory reviewer login, the video footage and the Show HN demo (D5).
   - It never contains the owner's real data.
7. **Claude Code plugin (optional).** Package the MCP config plus a short skill, so installing it is
   one command. Todoist ships the same form.
8. **Official MCP Registry.**
   - Write `server.json` with a `remotes` entry (`streamable-http`, the MCP URL).
   - Publish via `mcp-publisher` under `io.github.g7xu/…`.
   - Versions are immutable, so publish once this phase is green.

*Done when:* `docs/CLIENTS.md` shows at least four clients passing, every tool carries a title and
hint, the production smoke suite passes, and the demo account resets in one command.

### Phase 4: Open source and the write-up

1. **Real secret scan.** Run `gitleaks detect` over the full history. Rotate anything found.
2. **Remove personal data.**
   - Strip the email from the `**Owner:**` lines.
   - Take the owner's routine names and counts out of AGENT.md and ROUTINES.md.
   - Apply D2 to the history.
3. **Docs restructure.**
   - Reader-facing docs stay in `docs/`: MCP.md, CLIENTS.md, USAGE.md, DEADLINES.md.
   - Build history moves to `docs/design/`: PRD, TDD, PROMPTS, TRIAGE, ESTIMATES, DECISIONS.
   - The README keeps its landing-page shape and gains the demo GIF, the headline and badges.
4. **The write-up (D10).** "Giving your own app a remote MCP server with OAuth 2.1," an explanation
   piece drawn from `docs/MCP.md`. It covers:
   - why the app is its own authorization server;
   - CIMD versus DCR;
   - port-agnostic loopback redirects;
   - a `+` in `redirectTo` breaking sign-in;
   - a replay revocation rolled back inside `$transaction`;
   - what the black-box suites found.

   This is the Show HN anchor.
5. **Repo setup.**
   - Add the `LICENSE` (D1) and a short `CONTRIBUTING.md` (run against your own Neon project;
     issues welcome).
   - Set the GitHub description, topics (`mcp`, `oauth`, `todo`, `claude`, `nextjs`) and homepage.
6. **Make the repo public.**

*Done when:*
- gitleaks is clean;
- `git grep` finds no personal email or usage data;
- a clean clone plus `.env.local.example` runs locally;
- the write-up is published.

### Phase 5: Demo video

60–90 s, 16:9, recorded with Screen Studio (macOS) or QuickTime with manual zooms. Shot list:

1. **Open mid-session in Claude Code** on a real coding task. The user says "Add 'review PR
   feedback' for tomorrow, deadline Friday." The agent calls `create_task` without leaving the
   session.
2. **"How's my daily review routine going over the last four weeks?"** The agent calls
   `get_routine_history` and answers with numbers.
3. **"Move everything due today that isn't P1 to tomorrow."** The approval prompt appears, then the
   Upcoming board updates.
4. **A second client** (Cursor or Codex CLI) running the same prompt, with the one-line setup on
   screen.
5. **End card:** "No AI inside. Free. Open source." Then the URL and repo.

Export three versions:
- an unlisted YouTube video, which Product Hunt requires;
- a muted MP4 for the landing page;
- a GIF for the README.

*Done when:* the clip is on the landing page and in the README.

### Phase 6: Launch

1. **Show HN.**
   - Title on the build story, e.g. "Show HN: I gave my todo app a remote MCP server with real
     OAuth".
   - Link the repo and the write-up.
   - Offer the demo login (D5), stay present in the thread, and do not solicit votes.
2. **Claude directory.**
   - Submit at claude.ai/directory/manage (requires a Pro or Max plan) with:
     - the listing copy, 1–5 categories and the icon;
     - the docs, privacy and support URLs;
     - the reviewer account.
   - Expect a "Community" listing; Anthropic grants "Verified" on its own assessment.
   - Escalation: mcp-review@anthropic.com.
3. **Other directories.**
   - Smithery (`smithery.ai/new`).
   - Glama (claim via `/.well-known/glama.json`).
   - mcp.so.
   - PulseMCP ingests from the official registry.
4. **r/ClaudeAI and r/mcp.** Read each subreddit's current self-promotion rules first; these could
   not be fetched during research.
5. **Product Hunt (optional).** Two or more 1270×760 images, a 240×240 thumbnail, a tagline of at
   most 60 characters, and the YouTube video.
6. **Launch-day operations.**
   - Watch Vercel function logs and Neon compute.
   - The Neon free plan's 100 CU-hours per month is the first limit to hit.

  advertises 27.
- Which MCP clients register custom-scheme redirect URIs. Phase 3 measures this.
- Neon Auth one-time-code send limits, and whether Better Auth's rate limiter is on in the managed
  service.
- The Claude directory's icon dimensions (shown in the submission portal).
